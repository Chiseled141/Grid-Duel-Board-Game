# Cards.exe Launcher Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a small `Cards.exe` that starts a loopback Deck Duel server and opens the client, using the Java runtime already installed.

**Architecture:** A C# 5 launcher compiled by the Windows-bundled `csc.exe`. It resolves Java and `target/deck-duel.jar`, starts the server hidden when port 5555 is free, waits for the port, launches `javaw` with the client, and stops a launcher-owned server when the last client exits. Short-lived session markers under `data/.cards-launchers/` stop one launcher from killing the server while another is opening its client. A PowerShell integration script exercises the lifecycle; the generated exe is build output and stays untracked.

**Tech Stack:** C# 5 (`csc.exe` from .NET Framework 4.x), WinForms message boxes, WMI (`System.Management`) for process lookup, PowerShell 5.1 for integration checks, existing Java 17+ and Maven build.

**Spec:** `docs/superpowers/specs/2026-10-27-cards-exe-design.md`

## Global Constraints

- Windows 10/11 only; exe compiled with the bundled `csc.exe`, no new dependencies.
- Java 17 or newer must be found through `JAVA_HOME` or `PATH`; never bundle a runtime.
- `target/deck-duel.jar` must already exist; do not auto-build it.
- Server stays on `127.0.0.1:5555`, database `data/deck-duel.db`, log `data/server.log`.
- Never stop a server unless `data/.cards-server.pid` exists and names a live Deck Duel server.
- Do not modify game, protocol, Maven, or resource files.
- Generated `Cards.exe`, `data/` and logs stay untracked.

## Review Focus

- Java 8 appears before Java 17 on `PATH`: the launcher skips it and finds a newer JDK, or shows the Java 17 dialog instead of crashing.
- `target/deck-duel.jar` is missing: a clear dialog names `mvn package`; no server is left running.
- The jar was packaged with `deckduel.server.host` or `deckduel.update.url`: the launcher refuses it and starts no server or client, leaving the official launcher/updater in charge.
- Two `Cards.exe` launches: closing the first client leaves the server for the second; the last client stops it.
- A server started by `scripts\run-server.bat` (no marker): it survives every client exit.
- Port 5555 held by an unrelated program: the launcher treats it as a server, opens the client, and leaves that process alone.

- [x] **Step 1: Write `launcher-win/build-cards-exe.bat`**

Locate `csc.exe` under `%WINDIR%\Microsoft.NET\Framework64` then `Framework`; compile with `/nologo /target:winexe /optimize+ /reference:System.Windows.Forms.dll /reference:System.Management.dll`; output `..\Cards.exe`; print the output path on success and exit non-zero on failure.

- [x] **Step 2: Write `launcher-win/CardsLauncher.cs`**

Required members, C# 5 syntax only (no interpolation, `using var`, or expression-bodied members):

```csharp
static class CardsLauncher
{
    const int Port = 5555;
    const string Host = "127.0.0.1";

    [STAThread]
    static int Main(string[] args);
    static void EnsureLocalDevelopmentBuild(string jar); // packaged host/metadataUrl must be empty
    static string FindJava();                       // JAVA_HOME then PATH entries; major >= 17
    static int JavaMajor(string javaExe);           // parse `java -version` stderr
    static bool PortOpen();                         // 300 ms connect to Host:Port
    static int StartServer(string javaExe);         // hidden, logs to data\server.log, writes marker, waits 20 s
    static void LaunchClient(string javaExe);       // javaw if present, waits for exit
    static bool OtherClientRunning();               // WMI: deck-duel.jar + " client"
    static void StopLauncherServer();               // marker + no other client + process is a Deck Duel server
    static bool IsDeckDuelServer(int pid);          // WMI command line contains deck-duel.jar + " server"
    static void ShowError(string message);          // MessageBox, "Cards"
    static string Root { get; }                     // directory of the exe
}
```

Behavior details:

- Root-relative paths: `target\deck-duel.jar`, `data\deck-duel.db`, `data\server.log`, `data\.cards-server.pid`, `data\.cards-launchers\*.session`.
- After the jar exists and before creating `data/`, open the jar as a zip and read
  `deckduel/connection.properties` key `host` and `deckduel/update.properties` key `metadataUrl`.
  If either value is non-empty, show "This jar is packaged for a production server or release
  channel; use the installed launcher" and stop without starting anything. Unfiltered Maven
  placeholders (`${...}`) count as empty, matching the client.
- Register a session marker under `data\.cards-launchers\` before probing the port; hold the named
  mutex `Local\DeckDuelCardsLauncher` for registration, the port re-probe and cleanup.
- Server command: `java -jar "target\deck-duel.jar" server --port 5555 --db "data\deck-duel.db"`, `CreateNoWindow=true`, stdout/stderr appended to `data\server.log`.
- Wait up to 20 s for the port; if the server exits or times out, kill it, show the dialog with the log tail, and return 1.
- Client command: `javaw -jar "target\deck-duel.jar" client --host 127.0.0.1 --port 5555`, working directory `Root`; fall back to `java.exe` with `CreateNoWindow=true` if `javaw.exe` is absent.
- Cleanup runs in `finally`. Remove this session; stop the marked server only when no other live
  session and no other client process remains, and the marker PID is still a Deck Duel server.
  Verify the kill before deleting the marker; cleanup errors are swallowed so they never become a
  startup-error dialog.
- Process roles are matched by the `client`/`server` token immediately after a `deck-duel.jar`
  argument, so a path containing those words cannot misclassify a process.
- Errors: Java < 17 (`Java 17 or newer is required`), missing jar (`Run "mvn package" first`), server failure (last 10 log lines).
